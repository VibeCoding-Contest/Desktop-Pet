# 桌面桌宠 APP — 升级功能设计：自定义形象（图片导入）

> 本文档记录在 P0–P2 基础上的升级功能设计。本篇聚焦「自定义形象导入」：用户通过一张图片 + 少量元数据，即可新增一个桌宠形象（例如「科比」），并在菜单中切换使用，无需改代码、无需重新打包。

---

## 一、功能目标

让用户无需改代码、无需重启打包，即可：

1. 选择一张本地图片（角色立绘 / 照片 / 表情包，建议 PNG 带透明背景）
2. 填写少量数据（显示名、ID、可选尺寸 / 配色）
3. 一键注册为新形象，立即在右键菜单「角色」中出现并可切换
4. 重启应用后仍保留自定义形象

**典型用例**：用户导入一张科比照片 → 命名为「科比」→ 右键切换 → 桌宠变成科比在桌面走动。

---

## 二、现状与可行性分析

### 2.1 已具备的基础设施

`renderer/pet.js` 早已设计为「引擎 + 形象注册表」架构（见 `docs/FLOW.md` 会话 4/5）：

```js
// 已有的注册接口
Pet.registerType(name, renderer);
// renderer 契约：{ name, palette, draw(ctx, o), init?(pet): Promise }
```

引擎在 `Pet.draw()` 中已计算好动画意图（`bob / scaleY / tilt / eye / mouth / mouthOpen / legSwing`），套位移 / 缩放 / 倾斜变换后委托给 `renderer.draw(ctx, o)`，并向 renderer 注入 `o.utils = { eyes, mouth, tear }` 共享绘制工具。

### 2.2 形象层已有先例

`docs/FLOW.md` 会话 4 已给出贴图形象的扩展用法：

```js
Pet.registerType('fox', {
  name: 'fox',
  init: async (pet) => { /* 预加载图 */ },
  draw(ctx, o) { /* 按 o.state / o.phase 选帧 drawImage */ }
});
```

### 2.3 结论

**引擎层零改动即可支持图片形象**。本次升级的核心工作是：

- 提供一个「创建器」UI 收集图片 + 数据
- 提供工厂函数把数据转成 renderer 对象并注册
- 主进程增加文件级持久化（存图片 + 索引）
- 菜单「切换角色」从「硬编码数组循环」改为「动态枚举所有已注册形象」

## 四、数据模型

### 4.1 自定义形象配置 `CustomPetConfig`

```ts
interface CustomPetConfig {
  id: string;          // 唯一标识，如 'kobe'；作为 Pet.registerType 的 name 与图片文件名
  label: string;       // 显示名，如「科比」；用于菜单文案
  imageSrc: string;    // 图片数据：base64 data URL（创建时）或 file:// 路径（加载时）
  width?: number;      // 绘制宽，默认 64（与内置形象一致）
  height?: number;     // 绘制高，默认 64
  palette?: {          // 可选配色，影响附加元素
    tear?: string;     // sad 时泪滴颜色，默认 '#7EC8FF'
  };
  overlay?: {           // 可选叠加引擎自带表情
    eyes?: boolean;     // 是否按 state 叠加 eyes helper
    mouth?: boolean;    // 是否按 state 叠加 mouth helper
  };
  // 高级（后续扩展，不在本期范围）：
  // frames?: { idle?: string; walk?: string; ... };  // 按 state 分配不同图
}
```

### 4.2 持久化索引 `custom-pets-index.json`

存于 `app.getPath('userData')/custom-pets/` 目录：

```json
{
  "version": 1,
  "pets": [
    {
      "id": "kobe",
      "label": "科比",
      "imageFile": "kobe.png",
      "width": 64,
      "height": 64,
      "overlay": { "eyes": false, "mouth": false }
    }
  ]
}
```

图片本体存为同目录下的 `{id}.{ext}` 文件。

### 4.3 与现有 SaveData 的关系

**不污染原有 `pet-save.json`**。`saveState()` 仍只存 `pet.type`（即自定义形象的 id），加载时由 `loadCustomPets()` 已先行注册，可正常恢复。索引与存档完全分离，删除自定义形象不会破坏存档结构（恢复时若 type 缺失则降级为 'cat'）。

## 五、模块设计

### 5.1 `renderer/pet-image-factory.js`（新文件）

工厂函数：把 `CustomPetConfig` 转成符合 renderer 契约的对象并注册。

```js
// 契约：{ name, palette, init?(pet): Promise, draw(ctx, o) }
function createImagePet(config) {
  const img = new Image();
  let ready = false;
  const w = config.width || 64;
  const h = config.height || 64;

  return {
    name: config.id,
    palette: Object.assign({ tear: '#7EC8FF' }, config.palette || {}),

    init() {
      return new Promise((resolve, reject) => {
        img.onload = () => { ready = true; resolve(); };
        img.onerror = (e) => { ready = false; reject(e); };
        img.src = config.imageSrc;
      });
    },

    draw(ctx, o) {
      if (!ready) return;
      // 引擎已 translate(cx, cy+bob) + rotate(tilt) + scale(1, scaleY)
      // 这里只需把图片以 (0,0) 为中心绘制
      ctx.drawImage(img, -w / 2, -h / 2, w, h);

      // 可选：根据用户配置叠加引擎自带眼神 / 嘴
      if (config.overlay && config.overlay.eyes) {
        o.utils.eyes(ctx, -w / 5, -h / 8, w / 5, o.eye, 2.6);
      }
      if (config.overlay && config.overlay.mouth) {
        o.utils.mouth(ctx, 0, h / 6, o.mouth, o.mouthOpen);
      }

      // sad 时叠加泪滴（与内置形象一致，可由 palette.tear 调色）
      if (o.state === 'sad') o.utils.tear(ctx, -w / 4, -h / 4, o.phase);
    }
  };
}

// 便捷注册入口（返回 bool，与 Pet.registerType 一致）
function registerCustomPet(config) {
  return Pet.registerType(config.id, createImagePet(config));
}

if (typeof module !== 'undefined' && module.exports) {
  module.exports = { createImagePet, registerCustomPet };
}
```

要点：
- **复用引擎动画**：图片形象自动享有 idle 呼吸、walk 摆动倾斜、jump 抛物线、sit 压扁、yawn 张嘴（由引擎变换驱动，图片整体跟着动），无需自画关键帧。
- **可选叠加表情**：默认不叠加（保留原图神态），用户可在表单勾选「叠加眼神/嘴」让原图片随 state 变化眼睛/嘴。
- **泪滴统一**：sad 状态默认叠加泪滴，与内置形象行为一致。

### 5.2 `renderer/pet-creator.js`（新文件）

创建器 UI：一个浮动表单（可从右键菜单「添加形象…」打开），DOM 由 JS 动态创建，不污染 `index.html`。

职责：

1. **图片选择**：`<input type="file" accept="image/*">` → `FileReader.readAsDataURL` → 预览
2. **字段**：`label`（必填）、`id`（从 label 自动生成，可手改）、`width/height`（默认 64）
3. **勾选项**：是否叠加眼神 / 嘴、是否 sad 叠加泪滴
4. **实时预览**：用一个独立 canvas 跑临时 `Pet` 实例，边填边看效果
5. **提交**：
   - 校验：`id` 非空且未被 `Pet.TYPES` 占用；`imageSrc` 有效（`img.onload` 成功）
   - 调 `registerCustomPet(config)` 立即注册并切换预览
   - 调 `window.petAPI.saveCustomPet(config)` 持久化
   - 发 `pet:customAdded` 事件（菜单监听后刷新角色列表）
   - 发 `menu:switchPet({ type: id })` 直接切到新形象
6. **关闭**：`destroy()` 清理 DOM 与预览 RAF

UI 草图：

```
┌─ 添加自定义形象 ─────────────────┐
│  [选择图片]    [预览 canvas]     │
│  显示名：[科比            ]      │
│  ID：    [kobe             ]     │
│  尺寸：  [64] x [64]             │
│  ☐ 叠加引擎眼神                  │
│  ☐ 叠加引擎嘴部                  │
│  ☑ sad 时叠加泪滴                │
│  [取消]          [注册并使用]    │
└──────────────────────────────────┘
```

### 5.3 `main.js` 新增 IPC

```js
// ---------- 自定义形象持久化（升级功能）----------
const customDir = () => path.join(app.getPath('userData'), 'custom-pets');
const indexFile = () => path.join(customDir(), 'index.json');

function loadIndex() {
  try {
    if (!fs.existsSync(indexFile())) return { version: 1, pets: [] };
    return JSON.parse(fs.readFileSync(indexFile(), 'utf8')) || { version: 1, pets: [] };
  } catch { return { version: 1, pets: [] }; }
}
function saveIndex(idx) {
  fs.mkdirSync(customDir(), { recursive: true });
  fs.writeFileSync(indexFile(), JSON.stringify(idx, null, 2));
}

// 渲染进程传 base64 data URL → 写文件 + 更新索引
ipcMain.handle('save-custom-pet', (_e, config) => {
  const m = /^data:image\/(\w+);base64,(.+)$/.exec(config.imageSrc || '');
  if (!m) throw new Error('invalid imageSrc (expect data URL)');
  const ext = m[1] === 'jpeg' ? 'jpg' : m[1];
  const file = `${config.id}.${ext}`;
  fs.mkdirSync(customDir(), { recursive: true });
  fs.writeFileSync(path.join(customDir(), file), Buffer.from(m[2], 'base64'));

  const idx = loadIndex();
  const entry = {
    id: config.id,
    label: config.label || config.id,
    imageFile: file,
    width: config.width || 64,
    height: config.height || 64,
    overlay: config.overlay || { eyes: false, mouth: false },
  };
  const i = idx.pets.findIndex(p => p.id === config.id);
  if (i >= 0) idx.pets[i] = entry; else idx.pets.push(entry);
  saveIndex(idx);

  // 返回磁盘路径，供渲染进程立即可用（避免再带 base64）
  return { ok: true, path: path.join(customDir(), file) };
});

// 启动时读取所有自定义形象
ipcMain.handle('load-custom-pets', () => {
  return loadIndex().pets.map(p => ({
    id: p.id,
    label: p.label,
    imageSrc: 'file://' + path.join(customDir(), p.imageFile),
    width: p.width,
    height: p.height,
    overlay: p.overlay || { eyes: false, mouth: false },
  }));
});

// 可选：删除
ipcMain.handle('delete-custom-pet', (_e, id) => {
  const idx = loadIndex();
  const i = idx.pets.findIndex(p => p.id === id);
  if (i < 0) return { ok: false };
  const f = path.join(customDir(), idx.pets[i].imageFile);
  try { fs.unlinkSync(f); } catch {}
  idx.pets.splice(i, 1);
  saveIndex(idx);
  return { ok: true };
});
```

> 安全说明：Electron 渲染进程对 `file://` 协议图片默认可能受 `webSecurity` 限制。本期可在主窗口 `webPreferences` 中按需放开，或后续优化为注册自定义协议 `petasset://`（更安全，列为后续优化项，见 §十）。

### 5.5 `menu.js` 改造

把切换角色从「硬编码数组循环」改为「枚举所有已注册形象」子菜单：

```js
// 旧：const PET_TYPES = ['cat','dog','penguin']; switchIdx 循环
// 新：
function listPetTypes() {
  const builtins = [
    { id: 'cat', label: '猫咪' },
    { id: 'dog', label: '狗狗' },
    { id: 'penguin', label: '企鹅' },
  ];
  const customs = (window.__customPets || []).map(p => ({ id: p.id, label: p.label }));
  return [...builtins, ...customs];

```

并把「切换角色」改为「角色 ▸」**子菜单**，每项一个 `menu-item`，点击发 `menu:switchPet({ type: id })`。子菜单末尾加分隔线 + 「添加形象…」项，点击发 `menu:openCreator`。

## 六、数据流

### 6.1 创建并注册

```
用户右键 → 角色子菜单 → 添加形象…
  → menu 发 menu:openCreator
  → app.js 打开 PetCreator
  → 用户选图 + 填字段 + 点「注册并使用」
  → PetCreator:
      1. 校验 id 唯一 + 图片 onload 成功
      2. registerCustomPet(config)          // 立即可用
      3. window.petAPI.saveCustomPet(config)// 落盘
      4. emit('pet:customAdded', { id })
      5. emit('menu:switchPet', { type: id })  // 直接切过去
  → app.js 收到 menu:switchPet → pet.setPetType(id)
  → menu 下次 show 时 listPetTypes() 已含新项
```

### 6.2 启动恢复

```
app.js init()
  → const customs = await petAPI.loadCustomPets()
  → window.__customPets = customs
  → customs.forEach(c => registerCustomPet(c))   // 注册（各自 init 预加载图）
  → loadState()                                   // 此时若存的是 'kobe' 可正常恢复
  → ... status.start(); pet.startAutoBehavior(); ...
```

### 6.3 引擎渲染路径（不变）

```
requestAnimationFrame(loop)
  → pet.update(dt)   // 推帧/位移，与形象无关
  → pet.draw()
      → 引擎算动画意图 (bob/tilt/scaleY/eye/mouth/...)
      → Pet.TYPES[petType].draw(ctx, o)
      → 自定义形象的 draw：drawImage(img, -w/2, -h/2, w, h)  [+ 可选叠加]
```

## 七、边界与约束

| 场景 | 处理 |
|------|------|
| 图片过大 | 提交前用离屏 canvas 压缩到 ≤128px 并统一输出 PNG，避免 base64 膨胀与显存压力 |
| id 冲突 | 注册前校验 `Pet.TYPES[config.id]` 已存在则拒绝；表单提示「ID 已被占用」 |
| 非图片 / 损坏文件 | `img.onerror` → reject → 表单提示并阻止提交 |
| 图片非正方形 | 按 width/height 等比缩放居中绘制；默认填满 64×64 框（可后续支持「保持比例」选项） |
| 自定义形象被删除 | 索引移除 + 文件删除；若当前正使用该形象则切回 'cat' 并发 `menu:switchPet` |
| `file://` 安全策略 | 选项 A：主窗口 `webPreferences.webSecurity=false`（简单但不安全）；选项 B：注册自定义协议 `petasset://`（推荐，后续优化） |
| 图片透明背景 | PNG/WebP 原生支持透明；JPG 无 alpha 会有黑底，表单提示用户优选 PNG |
| 鼠标点击穿透判定 | `pet.getBounds()` 返回 `{x,y,width,height}`，自定义形象沿用引擎边界，`isOverPet` 无需改动 |
| 多 Pet 实例（dev.html） | factory 不持单例状态，`createImagePet` 每次返回独立 renderer + 独立 Image，dev 预览台可正常用 |

- **逐帧动画**：单张 sprite sheet 按 `o.phase` 切割帧，实现行走逐帧播放
- **形象市场**：从远程 URL 拉取形象包（zip 打包图片 + meta）
- **自定义音效**：`assets/sounds/` 关联到形象，状态触发播放
- **形象管理面板**：删除 / 重命名 / 导出 / 导入形象
- **自定义协议 `petasset://`**：替代 `file://`，更安全地加载本地图片资源
- **点击区域精细化**：按图片 alpha 像素判定命中，而非矩形 bounds（更贴合异形立绘）
