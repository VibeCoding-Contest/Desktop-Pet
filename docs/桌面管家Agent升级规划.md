# 桌面桌宠 APP — 桌面管家 / Agent 化升级规划

> 在已完成的"基础桌宠"（透明窗口 + Canvas 角色动画 + 状态/气泡/菜单/托盘/持久化）之上，
> 将桌宠从"会动的摆件"升级为"有形象的桌面管家 / Agent"——能聊天、能查天气并给穿搭建议、
> 能管理日程并定时提醒、能听懂自然语言指令并执行。
>
> 技术栈：Electron + HTML/CSS/Canvas（沿用）+ LLM API + 天气 API + 系统通知
> 状态：规划阶段，本文档不含代码实现
> 最后更新：2026-07-25

| F15 | 本地数据持久化 | ✅ |

### 1.2 核心问题（用户反馈）

1. **角色太小**：当前窗口 `220×220`、Canvas `200×200`、角色本体 `64×64`，视觉上偏小。
2. **无法调整大小**：`resizable: false`，用户无法自行放大缩小。

### 1.3 升级目标

把桌宠做成一个 **有形象的桌面 Agent**：

- 能和我**自然语言聊天**（接 LLM）；
- 我问"天气怎么样"→ 它回复天气并给出**穿搭建议**；
- 后台维护一份**日程表**，每天/定时提醒我要完成哪些任务；
- "我让它干什么就干什么"——**Agent**：听懂指令 → 调用工具 → 执行 → 汇报，全程保留可爱的角色形象。

> 设计哲学：**形象是壳，Agent 是核**。角色永远在桌面，对话/提醒通过气泡与可展开的侧边面板呈现，指令通过 Agent 内核调度各类"工具"完成。

## 四、各功能详细设计

### 4.1 G1 角色放大与缩放

**现状**：`main.js` 窗口 `width/height = 220`、`resizable:false`；`index.html` Canvas `200×200`；`pet.js` 角色本体 `width/height = 64`，绘制半径 `r:18`。

**方案**：

| 项 | 现值 | 目标值 |
|----|------|--------|
| 窗口 width/height | 220 | 360（默认放大 ~1.6x） |
| Canvas width/height | 200 | 320 |
| 角色本体 width/height | 64 | 110 |
| 绘制半径 r | 18 | 30 |
| resizable | false | true（允许拖拽边角） |

**缩放交互**：

- 滚轮在角色上滚动 → 调整 `scale`（0.6x–2.5x），Canvas 与窗口同步 resize。
- 右键菜单 → "放大 / 缩小 / 重置"。
- 尺寸写入持久化 `SaveData.pet.scale`，启动恢复。

**要点**：

- `resizable:true` 后需保留透明 + 无边框体验，仍用现有拖拽逻辑移动，缩放只改尺寸。
- Canvas 内部坐标系随尺寸缩放，角色坐标按比例换算，避免动画位移错乱。
- 透明白边：放大后透明区域变大，需确认 `setIgnoreMouseEvents` 穿透区域仍正确（hover 检测沿用现有逻辑）。

### 4.2 G2 / G3 聊天面板 + LLM 接入

**聊天面板 UI**：

```
┌─ 桌宠(角色) ─────────┬─ #chat-panel (可展开/收起) ──────┐
│   Canvas 角色        │ 💬 我：今天天气怎么样？           │
│   (idle/walk...)     │ 🐱 管家：上海 28℃ 多云，建议…    │
│                      │ 💬 我：提醒我9点开会              │
│                      │ 🐱 管家：已加入日程 ✓            │
│                      │ ┌─────────────────────────────┐ │
│                      │ │ 输入…                  发送 │ │
│                      │ └─────────────────────────────┘ │
└──────────────────────┴──────────────────────────────────┘
```

- 展开方式：双击角色 / 菜单"聊天" / 快捷键（如 `Ctrl+Shift+P`）。
- 多轮对话保留历史（内存 + 可选持久化）。
- 流式输出：LLM 返回逐字渲染，气泡同步显示首句摘要。
- 人设 prompt：管家性格 + 当前角色（猫/狗/企鹅）口癖 + 工具列表。

**LLM 接入策略**：

| 方案 | 说明 | 取舍 |
|------|------|------|
| 云端 API | OpenAI 兼容接口 / 通义 / 智谱 等 | 简单、需 API Key、有费用 |
| 本地模型 | Ollama + qwen2.5 等 | 离线、隐私好、需本地算力 |
| 混合 | 默认本地，复杂任务降级云端 | 推荐 |

- API Key 放本地配置文件（`.gitignore`），不进仓库。
- 统一 `llm.js` 封装 `chat(messages, tools)`，支持流式 + function-calling。

### 4.3 G4 天气查询 + 穿搭建议

**数据源**：

- 免费 API：和风天气 / OpenWeatherMap（需 Key）。
- 兜底：无 Key 时抓取公开天气页面（不稳，仅备用）。

**流程**：

```
用户："今天天气怎么样？"
  → Agent 识别意图 → 调 weather.getToday(city)
  → 天气工具：取定位/默认城市 → 调天气 API → 返回 {temp, cond, wind, rain}
  → 回传 LLM → LLM 综合"天气 + 穿搭建议"生成自然语言回复
  → 聊天面板 + 气泡显示
```

**穿搭建议规则**（LLM 可基于下列规则再润色）：

| 气温 | 建议 |
|------|------|
| ≥ 28℃ | 短袖短裤，注意防晒补水 |
| 22–27℃ | 薄长袖/短袖 + 长裤 |
| 15–21℃ | 长袖 + 外套 |
| 8–14℃ | 毛衣 + 外套，早晚加薄羽绒 |
| < 8℃ | 羽绒/棉服，围巾手套 |
| 雨雪 | 带伞，防滑鞋 |
| 大风 | 防风外套，注意高空坠物 |

- 城市定位：优先系统定位，无则用配置默认城市，可口头"上海天气"覆盖。

### 4.4 G5 / G6 / G7 日程表 + 定时提醒 + 自然语言建日程

**数据结构**：

```ts
interface ScheduleItem {
  id: string;
  title: string;        // 任务标题
  datetime: number;    // 触发时间戳（可空 → 全天/仅列今日清单）
  repeat?: 'daily' | 'weekly' | 'weekday' | 'none';
  done: boolean;       // 是否完成
  createdAt: number;
  note?: string;
}

interface ScheduleStore {
  items: ScheduleItem[];
}
```

- 持久化到 `userData/schedule.json`（沿用现有 `save-data` 思路，新增独立文件）。

**提醒机制**：

- `scheduler.js` 每分钟扫描到期任务 → 主进程 `Notification` 系统通知 + `bubble` 气泡 + 可选声音。
- 每日早报：首次启动 / 设定时间（如 8:00）汇总今日待办，气泡+面板播报。
- 重复任务到点后自动滚到下一周期。

**自然语言建日程**：

- "提醒我明天 9 点开会" → LLM function call `schedule.add({title:'开会', datetime:<明天9点>})`。
- 时间解析：LLM 直接产出 ISO 时间或由工具内部用 `date` 库归一化。
- "我今天的任务" → `schedule.listToday()` → 汇总回复。

**日程面板**（聊天面板的 tab 或独立子页）：

```
📅 今日日程            ＋ 新建
 ☐ 09:00 开会
 ☑ 12:00 午休           (完成)
 ☐ 18:30 健身
```

### 4.5 G8 Agent 工具系统

**核心思想**：把每个能力做成"工具"（含 name/description/parameters schema/handler），注册到注册表，LLM 通过 function-calling 自主选择调用。

```ts
interface Tool {
  name: string;                 // 'weather.getToday'
  description: string;          // 给 LLM 看的能力说明
  parameters: JSONSchema;       // 参数结构
  handler: (params) => Promise<result>;  // 实际执行
}
```

- `agent.js` 每轮把"人设 + 历史 + 用户输入 + 工具清单"发给 LLM；
- 若返回 `tool_calls` → 执行对应 handler → 把结果回灌 LLM → 生成最终回复；
- 全程角色形象不变，回复经气泡/面板呈现。

**首版工具集**：

| 工具 | 能力 |
|------|------|
| `weather.getToday` / `weather.getForecast` | 查天气/预报 |
| `schedule.add` / `list` / `complete` / `remove` | 日程增查完删 |
| `memo.add` / `memo.list` | 备忘便签 |
| `translate.run` | 翻译 |
| `search.web` | 网页搜索（返回摘要） |
| `system.openUrl` / `openApp` | 打开网址/应用 |
| `system.power` | 定时关机/休眠（经 IPC 主进程执行） |

### 4.6 G9 系统控制工具

- 打开网址/应用：渲染进程 → IPC → 主进程 `shell.openExternal` / `child_process` 启动。
- 关机/休眠：主进程执行 `shutdown -h now` 等，**需二次确认**。
- 音量/亮度：视平台支持，作为可选增强。

> 安全：涉及系统级操作一律弹确认气泡/面板，防止误执行。

## 八、风险与应对

| 风险 | 应对 |
|------|------|
| LLM API Key 泄露 | 放本地配置，`.gitignore` 忽略；提供本地模型兜底 |
| 天气 API 限流/失效 | 缓存结果、多源兜底、无 Key 时降级提示 |
| 放大后点击穿透区域错乱 | 复用现有 hover 检测，按新尺寸重算命中区 |
| function-calling 不稳定 | 工具描述清晰、参数校验、失败回退普通对话 |
| 系统操作误执行 | 二次确认 + 仅限白名单命令 |
| 跨平台通知差异 | 主进程统一封装，失败降级为气泡 |
| 隐私（对话/日程） | 全部本地存储，不主动上传 |
